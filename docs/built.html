familybox: what's built

One small box holds a family's SSNs, tax forms and health records. A verified NEAR enclave model answers questions about them, and the box decides what any assistant is allowed to see.

Foundation

The core

  • Verified, encrypted NEAR model

    Fresh attestation, end-to-end encryption, and an enclave signature checked on every turn. Anything else stops the question.

    done

  • Per-person files and answer gate

    Each person reaches only their own folders. Every answer is checked against the real stored SSNs, IDs and diagnoses before an assistant sees it.

    done

  • Assistant connection, upload page, approvals

    Assistants ask over MCP. Family members upload privately and approve held values on the box's own page.

    done

  • Drive import and encrypted backup

    Built and tested against a fake Google. Real use waits on an OAuth client.

    done

  • Attack suite

    30 attacks and 8 normal questions, three ways: through the box, without the gate, and with no protection.

    done

  • Running on the Raspberry Pi

    Installed on decision-tree through the fleet, no SSH. Tests and the replay demo pass on the board.

    done

  • Plugin hooks

    Extra tools, checks before and after each answer, and per-question events, so every feature below plugs in without touching the core.

    done

Built this round

Ten features

Each one was built on its own branch, reviewed by a separate agent, and fixed before merging. Eight are on main.

  • ChatGPT and Claude on the web

    The box is its own sign-in server. A family member approves an assistant with a one-time code, and that assistant only ever asks as them. Tokens rotate and can be revoked. Review closed an open redirect and moved assistants to their own listener.

    merged

  • Live trust panel

    An Activity page shows each question as a timeline: attestation, encryption, each signed turn, files opened or refused, and what the gate held. Admins never see other people's answers or file names.

    merged

  • Photo transcription, both copies kept

    A photo of a card or W-2 goes once to NEAR's enclave vision model, with location data stripped. The box keeps the original and a signed transcript, and starts protecting the numbers on it. Tested live with a fictional SSN card.

    merged

  • Fill forms on the box

    The assistant says which detail goes in which field. The box fills in the real values locally and every owner approves before the PDF can be downloaded. The assistant only sees a masked summary.

    merged

  • Alert when NEAR's code changes

    Fingerprints NEAR's gateway and model enclave. If anything changes, sensitive questions stop until the owner reviews it, and every decision is kept in a tamper-evident history.

    merged

  • Second check for reworded leaks

    One more verified enclave call asks whether the answer gives away a protected fact in other words. If that check fails, the whole answer is held. Adds 8 reworded-leak attacks to the suite.

    merged

  • Confidential analysis workbench

    The enclave model can write a short Python script that runs on the Pi in a sealed sandbox: no network, no new processes, only copies of the asker's files, with time and memory limits. Off by default, logged for the person.

    merged

  • Tamper-evident disclosure log

    Each person's record of what left the box is hash-chained, so a rewrite is detectable. A NEAR testnet anchor and contract are written and run as a dry run until there is a testnet account.

    merged

  • Approve button on the UNO Q

    Approve-only device tokens and a device API that never sees values, plus the board app and a simulator. Not yet tried on the board, which is offline.

    merging now

  • Red-team page for judges

    Pick a fictional family member and try to get Maya's SSN or Dana's medication out. Leaks are scored by the same checker as the attack suite. Hard daily spending cap. Local only until you approve hosting.

    built, merging next
