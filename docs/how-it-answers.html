familybox, tested 11 November 2026

How familybox answers a question

The assistant asks. A model inside a NEAR enclave reads the files and writes a draft. The box at home checks that draft against the real numbers before anything goes back.

What happens, step by step

One question, nine steps

  1. 1

    The assistant asks the box

    Maya's Claude sends "What is my SSN?" to the Pi. The connection itself says who is asking, so nobody can claim to be someone else.

  2. 2

    The box checks NEAR, then sends the question

    It verifies the hardware proof that the model runs in a sealed enclave, then encrypts the question to that enclave. If the proof fails, it stops.

  3. 3

    The model asks for files

    It replies with tool calls such as "search for SSN" and "read this file". It cannot touch the disk itself.

  4. 4

    The box runs the tools

    The Pi searches and reads on its own disk, only in Maya's folders and the shared one, and sends the text back encrypted. Steps 3 and 4 repeat as needed.

  5. 5

    The model writes a draft

    Each reply carries the enclave's signature, which the box verifies.

  6. 6

    The answer gate checks the draft

    Plain code on the Pi compares the draft with the real values it found in the files. It passes, masks, holds or refuses.

  7. 7

    A second model looks for rewording

    A different enclave model is asked whether the answer gives away a protected fact in other words. If that check fails or times out, the answer is held.

  8. 8

    The assistant gets the checked answer

    For Maya: "ending in 4322, held for Maya's approval".

  9. 9

    The full value goes to the owner's phone

    Maya taps approve on the box's page and sees all nine digits there. The assistant never does.

Where this differs from the sketch

The Pi redacts, not NEAR. NEAR's model can be talked into things. The gate cannot, because it only matches text.

The record stays home. The assistant gets the answer and its outcome. The step-by-step record stays on the box.

No bash. The model can search, read, read a photo and fill a form. An optional sandbox runs Python it writes, with no network.

Not built yet

A small model on the Pi that flags sensitive facts when a file is added, and a sandboxed shell tool. Neither is in this diagram.

These drafts were written by hand and run through the real gate with the fictional Okafor family's files. They test the gate, not the model. All numbers are made up.

Two things the tests turned up

  • A gap, fixed today. The gate did not catch an SSN written backwards or with every digit shifted, although the project's notes said it did. In four live runs the model refused those requests by itself, so nothing leaked. The gate now refuses them, and eleven new test cases cover it.
  • A gap that remains. The last row passes the gate, because there is no value to match. That is the job of step 7, the second model, and it is not perfect: across four live runs, 0 to 4 reworded hints got out per run, almost all about the asker's own record. No SSN or ID number got out in any run.
