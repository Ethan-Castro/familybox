The rules that decide this

What is allowed

  • Two projects at most per person, only if they are independent, and each README names the other.
  • One submission per project and per repo. Each email can file two.
  • Several tracks per submission is fine and still counts as one entry.
  • Code from Oct 19 on counts. Older projects are baseline; only new, separated work is judged.
  • AI screens first, humans decide. Claude Code and Codex check that each repo runs and does what its README says.

Lever 2

Add one separate project

Pick at most one. It needs its own repo and no shared familybox code.

  • Tidemark: a public change log for NEAR AI's enclaves

    Collectors verify every NEAR AI model's attestation on a schedule and record each change of code or measurements in a NEAR contract, with a small guard any app can drop in. Today's real drift is its first entry. Best fit: Security. Scored highest of the 12 concepts. Must be fresh code, framed as a public good, not familybox's pinning.

    3 to 4 daysbest second pick

  • Tenant Zero: probes for cross-customer leaks

    Preregistered canary tests that check whether one NEAR AI customer can detect another's prompts (cache timing first), each verdict pinned to the live measurement. Cheap in tokens, but needs a second org's credits, and probing the sponsor is awkward with its founder judging.

    3 daysrisky

  • Parallax: prove roughly where the model ran

    Time attestation round trips from several regions; light speed bounds the distance to the enclave, posted on NEAR. Very novel, but the bounds may come out continent-sized, which would show nothing.

    2 hour spike firstrisky

  • Overlap: sealed negotiation through an enclave

    Rival parties seal briefs to an attested model that returns one bounded verdict. Our own review found a fatal flaw: anyone holding a sealed brief can resubmit it and read the answer.
